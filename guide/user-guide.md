# 日常使用

[返回产品介绍](../README.md) · [开始使用](quick-start.md) · [CLI 参考](cli.md)

## 在哪里交代工作？

| 入口 | 用途 | 消息去向 |
| --- | --- | --- |
| 私人助手（侧栏 Panel Agent） | 咨询、整理需求、观察全部团队、提出转交请求 | 私人会话；不会把所有聊天自动复制给团队 |
| 团队页面 | 给该团队交代工作、补充信息、查看汇总 | 发给本团队当前主 Agent，忙碌时排队 |
| 成员与会话视图 | 查看成员分工、能力与双人会话记录 | 用于了解协作过程，不表示成员共享同一上下文 |
| 随心记（侧栏独立入口） | 先记下还没想清楚的想法；需要时带到私人助手继续讨论 | 记录本身不发送；点“交给 Panel Agent”才生成一条提示词，由你确认后发送 |

私人助手将需求转交团队后，可以通过来源链接进入团队查看；团队回执带有来源引用。团队直接聊天也不会自动复制到私人记录里。私人助手收到团队来源通知，不会因此自动启动模型回合。

## 创建与组织团队

页面建群先填写需求和工作文件夹，默认只读；需要成员生成或修改文件时，明确选择允许修改工作文件夹。主 Agent 负责协调和汇总，成员在各自会话中执行与交流。

私人助手也可根据明确需求创建团队。它观察团队共享记录，并可通过互动卡征询用户是否接管或交还主 Agent 的协调职责；同意后才切换控制关系。

分工、审阅、进展和交付由 Agent 在真实消息中组织。可选的任务面板展示成员写出的任务列表，不能把它当作自动核验工作质量或强制执行流程的保证。

## 参与关键选择

助手需要明确选择或补充信息时，会显示互动卡。卡片可能是几个选项，也可能要求输入一段文字。回答后，发起者会收到用户消息并继续处理：主 Agent 进入团队调度会话，普通成员进入独立的“用户 ↔ 成员”会话；私人助手的答复返回私人会话。普通成员的答复不一定回到原来的成员协作会话。

互动卡和团队说明是上下文与征询，**不是文件权限授权门禁**。成员能否读写项目仍由群执行策略与宿主沙箱决定。团队说明可以写目的、参与分工、边界和交付要求，但不能扩大实际权限。

## 资料与交付

- 私人助手支持 TXT、PNG 附件副本，限制可在设置中调整；服务端做最终验证。当前不支持 PDF、Office 等文件作为此附件入口的上传格式。
- 文件夹通过私人助手设置或团队创建入口选择。私人工作区与团队工作区独立。
- 回复中的本地文件链接可以下载当前工作区内的普通文件。超出范围、符号链接越界或框架内部数据会被拒绝；这不是一个任意浏览本机文件的文件管理器。
- 成员说“完成”不等于已经通过独立审阅。可要求它给出结果文件、验证方法和实际消息引用，再决定是否继续。

## 工作台、搜索和常用片段

主页集中显示待处理事项、运行活动、最近执行，以及手动生成的进展摘要。摘要会调用私人助手模型，不是后台持续自动生成的报告。

待处理卡片的下拉框区分三类数据：待你处理（Agent 发起的互动卡）、等待回复（用户指令超过 5 分钟仍无最终回复）和 Agent 等待（Agent 之间的请求超过 5 分钟仍无回复）。旁边的清理按钮只把当前选择范围从工作台隐藏，消息记录和回复关系不会删除；互动卡清理后仍保持待处理，可以在对应团队会话中继续操作。清理前会弹出确认，避免误触。

使用侧栏搜索或 `⌘K` / `Ctrl+K` 查找团队、成员、历史消息、页面和设置。输入框的常用片段可以插入指令；编辑后由用户手动发送。消息菜单支持引用，方便继续讨论已有内容。

## 随心记

侧栏「随心记」用来先记下还没想清楚的事：只有正文必填，标题自动取第一行，待办和截止都可不填。记录只有三种状态——正常、已完成、已归档；它不跟踪任何执行进度。

在团队页面的右栏「工具」里也能记一笔，那条会带上**来源团队**：记完立刻能看到本团队最近几条，也可以点「查看全部」到随心记页面只看该团队的记录。来源只是「这笔是在哪个团队里记的」，不是归属——团队被删除后记录仍在，来源显示为「团队已删除」。随心记页面默认显示全部记录，顶部可按团队（或「无来源」）筛选。

想把想法交给助手时，点「交给 Panel Agent」，页面会带着这条记录跳到私人会话，并把一段说明填进输入框（由你按发送）。助手会先读懂记录、结合当前工作区的实际情况判断它是否已经可以直接做：已经清楚就直接说怎么做并问你何时开始；有卡点就只列真正影响做对的地方；信息不足就问必须回答的问题。它不会在你明确同意前动手，也不会自动改写这条记录。

建议需要更新到记录里时，复制助手给出的版本手动保存即可。归档只把记录从主列表收起，可随时恢复；永久删除只对已归档记录开放，删除后不可恢复。

## 归档与恢复

归档停止团队投递并保留历史；可以从设置恢复。归档不是“工作质量已验收”的状态，也不会删除工作文件。永久移除成员会结束该角色并撤销访问；其名称在团队历史中保持唯一。

## 遇到问题

| 情况 | 建议操作 |
| --- | --- |
| 工具未安装或不可用 | 查看原因；在对应宿主中处理安装、登录或配置，再重新检测 |
| 请求超时 | 先刷新状态确认结果，使用原请求的重试入口，避免重新创建团队 |
| 消息失败 | 查看错误；重试保留原指令编号，不把失败当成已执行 |
| 出现待核实运行 | 先核实对应宿主进程是否实际停止，再使用核实入口；框架不会自动重放 |
| 重启后私人聊天为空 | 点击“历史记录”；新启动的私人聊天与此前记录分开显示 |

更完整的运行边界见[限制与安全](limitations.md)。
