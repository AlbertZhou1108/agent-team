# 异常与恢复

先读取相关消息、运行记录与宿主返回，区分消息已记录、宿主已接受输入、回合结束和结果正确。使用公开 CLI、面板或实际暴露的团队查询工具；不直接改数据库或读取控制凭据。

| 情况 | 处理方式 |
| --- | --- |
| 网络超时、操作返回丢失 | 先查实际状态；保留原请求编号或 operationId，通过原入口核对和重试，避免重复建群或派发 |
| 相同消息 ID 再次送达 | 核对本会话已执行内容和副作用；这是同一输入，新的运行 turnId 不代表新任务 |
| 输入发送失败 | 核对宿主是否接受或执行，再决定是否用 `/retry` 重试未成功发送输入；普通失败不会自动重试 |
| 模型容量、额度、认证错误 | 报告原始原因与影响；账号、登录和服务配置由宿主管理。更换模型使用有效目录和当前确认流程，不静默切换 |
| 重启或中断 | 保留原数据目录；查看待核实运行，不能因为内存中没有进程便断言宿主已停 |
| unknown 运行 | 给出运行编号与依据缺口；实际核实宿主已停后，使用 `/resolve 运行ID 核实依据` 或面板核实入口。解除阻塞不会自动重放 |
| 团队已归档 | 按用户需要恢复团队后继续；归档不删除历史，也不证明成果完成 |
| 不支持所需文件策略 | 说明当前宿主能力，选择经允许的策略或成员；不绕过限制或假装已验证 |

`/stop` 是尽力中断，不是停止成功的证明。重试、停止、解除待核实状态与删除分别是不同动作，按用户实际要求执行。

跨平台源码测试使用 fake host；真实宿主验收会消耗账号额度，应在隔离目录并遵守用户指定范围。恢复报告说明故障、确认的影响、采取的动作和未确认事项；截断事件不当作完整宿主历史。
