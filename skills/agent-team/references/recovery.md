# 异常与恢复

先读取当前协作状态和相关消息/运行记录，确认影响范围。查询本身不授权重试、终止或扩大权限。

| 情况 | 下一步与停止条件 |
| --- | --- |
| 管理 revision 冲突 | 重新 collaboration_read；结合已发生变化重作判断，不盲目换版本覆盖 |
| 操作返回丢失 | 相同 operationId 与相同命令用于幂等核对；命令变化使用新编号。冲突导致命令修改也使用新编号 |
| 相同消息编号重发 | 视为同一输入，核对上下文、已有成果及副作用；每次运行 turnId 可以不同 |
| 输入发送失败 | 核对宿主是否已接受及是否执行；用户可用 /retry 重试尚未成功发送的输入。已接受不等于完成，未确认接受也不能排除执行 |
| 进程中断或重启 | 使用原数据目录恢复；核对失败和 unknown 运行，不因内存为空认定宿主已停，不自动重放有副作用的工作 |
| unknown 运行 | 提供需核实的运行编号与依据缺口；用户实际核实停止后通过 /resolve 记录依据，不编造核实结论 |
| 模型或权限不支持 | 报告宿主和策略限制；重新选择经允许的成员或请求契约变更，不静默换模型、换身份或扩大权限 |
| 必要条件缺失 | 保留 blocked，继续独立且仍获授权的工作；说明用户需要决定什么 |
| 收尾被未处理消息拒绝 | 读取返回编号对应内容，处理后补 dispositions，重新提交；不因此改称未完成或伪造成功 |
| closing 尚未结束 | 核对活动运行、未处理消息和不确定运行；需恢复工作时使用允许的撤回入口，closed 后不能重开旧目标 |

## 用户干预与隐私

中断后按用户最新指令处理；明确停止、仅查询或限定工具时不自动恢复执行。不能用修复为理由代替用户批准契约、终止目标或删除团队。

用户私聊不复制到共享上下文。诊断使用公开查询入口，不输出 socket 控制 key、认证链接中的秘密或宿主凭据。面板事件受宿主暴露范围限制，尤其截断内容不能当作完整原始历史。

报告恢复结果时分别说明：观察到的故障、已确认影响、实际执行的恢复动作、尚未确认事项。发送成功、宿主接受、回合结束、成果接受与目标完成保持区分。
