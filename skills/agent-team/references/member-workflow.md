# 成员协作与审阅

## 接收工作

确认当前身份、收到的消息、工作目录、实际策略和负责范围。用 `members` 查成员；需要历史正文时遵循[完整消息读取](conversation-agent.md#读取完整消息)。同一消息 ID 再次出现时核对已有结果与副作用，避免重复操作。

profile 回合只需 `profile_set` 写本人能力自述，然后结束。能力自述用于理解分工，不是能力认证或权限授予。

## 执行与汇报

在实际宿主策略允许的范围内执行。共享文件先明确修改归属；遇到并发修改保留对方内容，向主 Agent 协调交接。

用 `tasks_set` 整体更新自己的任务列表（doing/done/dropped），只同步进度。需要对方处理时用 `send(to,text)`；需要对方明确答复或确认时设置 `expects_reply=true`；答复某条请求时把 `reply_to` 设为原消息 ID。补充且不需立即处理时用 `note`。send 每次指定一个接收者，需通知多人时分别发送。

交付通过 send 汇报成果位置、当前版本、实际验证、限制与问题；宿主最终文本不会自动进入群记录。不要求固定模板，不额外要求业务编号。

## 独立审阅

按约定检查当前文件或原始证据，说明检查范围、发现、必要修正与未验证事项。尊重“不修改文件”等明确约束；角色名称不会改变宿主沙箱权限。

审阅结论发送给负责修订者及主 Agent，引用实际版本；文件更新后旧结论不能自动覆盖新内容。材料缺失或额度不足时如实说明无法完成核验。

## 阻塞与等待

权限不足、依赖缺失、目录冲突或不可确认的副作用应报告影响与缺口，再推进仍可独立完成的部分。当前无可推进工作时结束回合，由框架接收下一条消息；不启动宿主原生子 Agent 或阻塞等待。

需要用户明确选择或补充信息时用 ask，并把必要上下文写在问题中；答复会进入“用户 ↔ 成员”会话。文件权限仍以该回合实际策略为准。
