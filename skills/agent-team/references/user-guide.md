# 用户操作指南

## 定位与启动

先确定 Agent Team 仓库位置、任务工作区、数据目录和宿主选择。不要将当前任务仓库自动当作框架仓库，也不要猜群编号、固定面板端口或认证链接。

在 Agent Team 仓库中运行；若环境未准备好，先核对 README、Node 要求和依赖状态。启动会使用真实宿主认证并产生模型调用，遵守用户指定的成员和模型预算。

```bash
# 新团队：先进入准备对话，用户确认后才创建
npm start -- --lead codex --members 助手=dsh --workspace /任务项目绝对路径 --data /团队数据绝对路径

# 恢复已有群；保持原数据目录
npm start -- --group 群编号 --data /团队数据绝对路径
```

使用独立总线时，先运行 serve，再连接 chat。已有总线时复用，避免重复启动同一数据目录。完整选项查询仓库 README 或 `node src/cli.mjs --help`；npm start 会先构建面板。

```bash
npm start -- serve --data /团队数据绝对路径
npm start -- chat --group 群编号 --data /团队数据绝对路径
# 外部会话查询状态，要求已有总线
npm start -- state --group 群编号 --data /团队数据绝对路径
```

## 表达任务

例如：“在指定项目实现 X，允许修改 A 范围和运行必要测试，不提交 Git、不部署。执行者实现，审查者检查最终版本。交付成果、验证依据和剩余问题。”

主 Agent 整理目标、范围、边界、确认事项、交付、完成条件和权限；用户核对实际契约，准备对话中 `/contract` 查看，`/approve` 展示并确认当前版本。审批由用户在可信入口完成，Skill 不代替审批。

## 团队中的操作

| 意图 | 交互命令与含义 |
| --- | --- |
| 询问、解释、查询 | 普通输入进入主 Agent 私聊，不自动进入群 |
| 明确共享执行指令 | `/direct 文本` 写入团队调度，不复制其他私聊 |
| 查看契约和工作状态 | `/state`；`/requests` 也返回协作状态和请求 |
| 查看成员 | `/members` |
| 决定待批准请求 | `/decide 请求ID yes\|no`，确认展示的具体请求 |
| 添加成员 | `/add 新名称=宿主`，按框架确认流程处理 |
| 停止一个成员当前回合 | `/stop 名称`，尽力中断，不移除身份、不代表目标完成 |
| 移除成员 | `/remove 名称`，先处理未完成责任；身份永久结束，历史名称不再复用 |
| 终止无法完成的目标 | `/terminate 原因`，保留未完成事实和 incomplete 结果 |
| 撤回尚未结束的收尾 | `/reopen 原因`，不用于重开已关闭目标 |
| 核实不确定运行 | `/resolve 运行ID 核实依据`，先有真实停止依据 |
| 重试未成功发送输入 | `/retry`，先核对输入接受情况及可能副作用 |
| 切换群 | `/groups`、`/use 群编号` |
| 删除群 | `/delete`，用户确认后删除框架配置与消息，工作文件和宿主历史保留 |
| 退出 | `/quit`；自带总线的 start 退出会关闭该总线，独立 serve 分别管理 |

不要自动执行批准、终止、删除、移除等操作来解决普通查询。用户授权了具体操作时按现有可信流程处理。

## 看板与后续目标

面板链接使用本次启动提供的入口。团队页可查看共享消息、工作项、审查、运行与交付，并可通过输入框向当前 Main Agent 发送团队指令；主 Agent 忙碌时排队，页面显示排队、投递或失败状态。指令不会触发契约审批，也不会广播给所有成员。用户私聊不展示。Goal Draft 确认、终止、接管等操作只通过各自的可信按钮和专用接口完成，不开放通用 RPC。全局模型策略不追溯改变已有角色。

目标 closed 后仍能交流。用户要求新执行任务时，调度 Agent 提出完整新契约，用户批准后启动下一目标版本。退出或停止进程不删除团队，也不能作为工作完成证明。
