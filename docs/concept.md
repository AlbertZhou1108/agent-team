# Agent Team 产品概念

日期:2026-10-25(ADR 0004 后重写)
状态:当前实现产品模型

Agent Team 是本机、单用户的 CLI Agent 通信框架。核心是一条多 Agent 消息总线:用户与主 Agent 对话,成员通过 `send/note/read` 在双人会话和统一调度会话中协作。框架负责身份、消息路由、回合调度、宿主策略与投递安全;任务分工、进度和完成标准由 Agent 在群消息里自行组织,框架不做流程状态机约束。

## 1. 产品边界

- 单用户、本机运行;数据保存在本地 SQLite,不依赖外部服务。
- 用户是唯一真人入口,不是群成员。用户私聊不自动进入团队共享上下文。
- 主 Agent 是用户当前对话中的 Agent,也是群内唯一承担协调职责的成员。
- 普通成员通过真实宿主会话工作,用自然语言群消息汇报。
- 面板用于观察消息、成员、沟通状态、运行事实与遥测;归档/恢复是唯一的群级状态操作。
- 当前接入 Codex app-server、Claude Code print、DSH headless;其他宿主走适配器。

## 2. 核心对象

| 对象 | 含义 |
| --- | --- |
| 群 Group | 一个长期团队空间、共享工作目录和成员集合;状态只有 open/archived |
| 成员 Member | 永久角色身份;名称在团队历史唯一;删除后身份终止 |
| 消息 Message | 一位发送者发给一位接收者的正式消息、留言或系统通知;正文不可改写 |
| 回合 Turn | 框架驱动一次宿主运行的尝试;与消息编号、宿主会话编号分别记录 |
| 团队说明 Charter | 建群时可选的一段纯文本,随回合注入上下文;不是授权门禁 |

没有目标、契约、工作项、审查、收尾等框架对象。这些协作概念由 Agent 用消息自组织。

## 3. 会话与调度

- 成员发给主 Agent 的正式汇报进入唯一 coordination 会话,串行;不同成员的双人对话可并行。
- 用户私聊独立;明确共享的指令经 `/direct` 进入调度上下文。
- 主 Agent 等待新信息时结束回合,不用原生子 Agent 或阻塞等待。
- 建群是直接操作:CLI 参数或 Panel Agent 的 `team_create`;成员入群自述能力。

## 4. 授权与策略

- 群执行策略为 `communication | read-only | workspace-write`,建群时确定;主 Agent 调度会话恒为 communication,成员双人对话按群策略获得宿主沙箱内的项目访问。
- 宿主工具裁剪与沙箱是真实的执行边界;框架把有效策略归入 communication/project 两个逻辑域,Adapter 决定物理会话复用或切换。
- charter 是上下文不是权限;宿主策略覆盖"该回合暴露给模型的工具",不等于整机隔离。

## 5. 消息与恢复

- 输入重发保留原消息编号;普通失败不自动重试。
- 重启时未明确结束的运行标记为待核实(unknown),阻塞投递,需用户核实;绝不自动重放可能有副作用的输入。
- 归档停止投递,恢复后继续;消息历史永久保留。

## 6. 完成与协作质量

任务完成没有框架审计。主 Agent 在消息中给出结论和证据(真实消息编号),用户决定是否归档、追问或继续派活。分工、质量把关、审查独立性由主 Agent 和用户在消息层面维护;若实测证明自组织不足,再考虑以可选层加回流程(见 ADR 0004 的后果一节),而不是恢复默认状态机。
