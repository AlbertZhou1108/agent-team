# 共享会话工作区

Panel Agent 与团队页面均使用 `web/src/features/messages/ConversationWorkspace.vue`。业务容器只负责查询、消息适配、发送和团队关系；公共组件负责标题、描述、消息工具栏、错误及重试、加载、历史分页、滚动、运行流展示与输入区布局。输入行为继续统一使用 `MessageComposer`，Panel 的模型/权限控件经其 controls 插槽扩展。

## 插槽边界

- leading / heading-meta / actions：标题图标、成员/主控信息及操作。
- status / context：局部状态与会话关联内容。
- empty：业务空状态和建议问题。
- footer：带 message 参数的业务回执。
- composer：两边基于同一个 MessageComposer 的业务适配器；readonly 时统一隐藏。

消息属性契约位于 `message-feed-types.ts`。流数据保持取值函数传递，不在工作区求值，避免每个 token 引起外层重渲染。两边使用相同滚动样式，团队不再通过组件 key 强制重建列表，而使用 resetKey 复位。Panel 全局/历史模式也使用不同 resetKey；团队系统通知默认分组，Panel 可以明确关闭分组。

## 验证（2026-10-30）

类型检查、100项前端测试、159项后端测试及生产构建通过。新增工作区测试覆盖只读时输入隐藏、业务回执与模型操作插槽保留、默认通知分组和Panel覆盖、错误及重试展示，以及工作区不求值流函数。

在开发环境5173实际检查两个页面的长历史内容、标题、输入区、Panel历史切换、模型弹窗打开/Esc关闭并返回焦点、键盘展开输入区、两边浅深主题及390px窄屏。修复公共滚动区flex最小宽度导致的消息横向溢出，以及长互动选项的撑宽。已恢复系统主题、默认视口和展开的输入区。

没有提交真实消息、修改模型或权限；实际发送/停止、新增消息跟底、网络失败后的交互重试及深历史翻页未做本轮端到端验证。保留既有相关测试和原有业务实现。构建仍提示部分产物大于500KB。

成员运行状态卡与输入区共用底栏，顺序为运行状态卡、输入框；不再放在输入框下方的面板 footer。
