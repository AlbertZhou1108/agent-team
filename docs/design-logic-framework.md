# 设计逻辑框架:元素的描述模型(草案)

本文是设计逻辑架构,回答两个问题:**一个页面元素由哪些方面描述**、**每个方面由谁决定**。它是 [frontend-architecture.md](frontend-architecture.md)(技术架构:代码放哪)的上游 —— 逻辑先于技术,技术层是本文的投影。

状态:草案,待确认后作为技术架构与后续打磨(材质等)的决策依据。

## 1. 元素的描述模型

> **一个元素 = 一个语义角色,在某个交互状态下,沿五个方面的取值组合。**

五个方面中四个来自讨论共识(样式/材质/行为/布局),一处拆分、两处新增(见 §2 说明)。

## 2. 五个方面

### 2.1 样式 —— 元素"是什么颜色、什么形状"

语义颜色(背景/前景/强调/危险)、形状(圆角/边框/描边)、图标语言。回答"品牌长什么样"。

- 决策源:全局主题偏好(用户选)→ 角色默认 → 组件消费。
- 技术投影:主题维度(29 token,含 radius)。

### 2.2 排印(阅读)—— 文字"读起来多舒服"【从样式拆出】

正文大小、行距、内容宽度、代码字号。与 2.1 拆开的理由:二者变化频率与决策者不同 —— 样式跟品牌走,排印跟阅读偏好走;换主题不应重置阅读设置。

- 决策源:全局阅读偏好,独立于其它方面。
- 技术投影:阅读维度(--reading-*/--code-size)。

### 2.3 材质 —— 表面是"什么物理质感"

玻璃(透明/模糊/高光)、纸张(哑光/纹理)、水泥(粗糙)。材质是物理隐喻,由五个内部要素构成:透明度、模糊、纹理、粗糙度、高光与边缘。立体感(阴影)属于材质内部参数。

**材质不为组件单独声明,而为"角色"声明**(见 §4):每种材质给出"每个角色上我长什么样"的适配(玻璃在阅读面降级为实色,就是一条材质×角色适配规则)。

- 决策源:全局材质偏好 × 角色适配规则。
- 技术投影:材质维度(data-material)+ 表面角色选择器。

### 2.4 行为 —— 元素"如何动态地变化"

元素因交互或状态变化产生的动态效果(用户原话:展开、收起、被点击、出现/消失)。行为 = **触发 × 过渡 × 循环**:

- 触发语义:用户交互(点击/悬停/拖拽)| 状态变化(出现/消失/展开/收起/加载/错误)
- 过渡规格:时长、缓动、幅度 —— 全部来自全局动效风格档,组件不自定数值
- 循环:加载点、脉冲等持续动画

- 决策源:全局动效风格档 × 用途语义(反馈/展开收起/浮层进出/内容出现)。
- 技术投影:动效维度(data-motion)+ 动效契约(pace × 时长缓动档)。

### 2.5 布局 —— 元素与元素"怎么排"

三个子问题:

- **密度**:间距、行高、容器留白 —— 松散/紧凑(用户原话)
- **遮挡**:谁在上谁在下(浮层层次、粘性侧栏)
- **滚动归属**:长内容在哪滚、几层嵌套

- 决策源:全局密度偏好 × 结构骨架。
- 技术投影:密度维度(--density-*)+ 结构骨架类 + z-index 刻度。

## 3. 状态 —— 贯穿五个方面的轴【新增】

默认、悬停、焦点、选中、禁用、加载、错误、待确认。状态不是第五个"方面",而是**其余方面共同沿它变化的轴**:成员行 = 默认样式下的成员行 + 悬停样式下的成员行 + ……

规则:任何状态的任何方面变化都必须有描述;状态表达不得只依赖一个方面(颜色不承载唯一信息)。

- 技术投影:语义状态表(DESIGN.md 验收表);未来演进:状态层令牌(悬停 = 表面色 + 固定透明度叠加,而非独立色值)。

## 4. 角色 —— 描述的索引【新增】

描述一个元素的第一句话是它的**角色**:导航面板、上下文面板、会话操作区、阅读面、浮层、媒体浮层。角色是五个方面取值的默认载体 —— 换角色 = 换一整套默认描述;材质/密度等维度的"作用范围"也以角色为界。

- 技术投影:表面角色体系(角色类 + 属性选择器)。

## 5. 决策层级 —— 每个方面由谁决定

| 层级 | 决定什么 | 例 |
| --- | --- | --- |
| 全局偏好(用户) | 五个方面的风格取向 | 深色 + 松林 + 玻璃 + 柔和 + 标准 |
| 角色默认(设计系统) | 每个角色在每个方面上的适配 | 玻璃在阅读面降级实色;浮层不做透明 |
| 组件实现(业务) | 用什么角色、放什么内容、业务差异 | 成员行用 Item;错误就近用 Alert |
| 实例(页面) | 极少数真实业务差异 | 拖拽把手必须可见 |

规则:下层只能在**不违反上层**的前提下做业务差异;组件层零视觉决策。

## 6. 可靠性规则(框架自检)

1. **归属完备**:任何视觉变化必须能归入"一个方面 × 一个决策层级";归不进去 = 框架缺陷,补框架而不是加特例。
2. **正交可判定**:方面之间互不覆写;任意(角色 × 方面 × 状态 × 偏好)组合有唯一确定结果 —— 组合解析规则显式化(如"材质 × 角色"适配矩阵)。
3. **状态完备**:每个角色的每个语义状态都有五方面描述。
4. **偏好不破坏可读性**:"材质 × 角色"适配是唯一允许偏好让步之处。
5. **用户维度即契约**:组件对维度无感知;维度落地必须伴随可感知的表面消费(样例卡 + 真实表面同步)。

## 7. 逻辑 ↔ 技术映射与现状

| 逻辑方面 | 技术承载 | 现状 |
| --- | --- | --- |
| 样式 | 主题维度(29 token) | 完整 |
| 排印 | 阅读维度(--reading-*) | 完整 |
| 材质 | 材质维度 + 表面角色 | **缺口:材质×角色适配矩阵未补全**(阅读面/浮层未声明;组件可不经角色直接 bg-card) |
| 行为 | 动效契约 + 用途语义 | 完整 |
| 布局 | 密度变量 + 结构骨架 + z-index 刻度 | 完整 |
| 状态 | 语义状态表 | **缺口:状态层令牌未建立**(悬停透明度散在各组件) |
| 角色 | 表面角色体系 | **缺口:角色未强制化** |

## 8. 由框架推出的下一步(供决策)

1. **补全"材质 × 角色"适配矩阵** —— 材质维度打磨的前提(纸感等新材质即矩阵新行)。
2. **状态层令牌** —— 状态描述进契约(悬停/按压 = 表面色 + 标准透明度叠加)。
3. **角色强制化** —— 新表面必须挂角色类,架构文档已列规则,可加检查。
