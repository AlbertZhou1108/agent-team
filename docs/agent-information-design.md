# Agent 信息访问与上下文成本方案

日期：2026-10-23
状态：设计定稿；生产逻辑尚未实施

## 决策

保留现有独立会话、多边交流、角色职责、模型策略和权限模型，优化框架向 Agent 提供信息的方式。

采用**确定性投影、必需事实直接提供、长材料按需展开**。权威数据完整保存，不用模型摘要代替事实，不把“少给信息”本身当作优化成功。默认先去掉无关历史和存储冗余，不能先截断任务、规格、源码和证据。

本次定稿的是可实施的范围与边界，不是承诺所有任务都节省费用，也不表示生产入口已接入或全部宿主行为已验收。

## 验证依据

实验与原始结果均在 `experiments/information-cost/`：

- [首轮隔离实验](../experiments/information-cost/RESULTS.md)：确认完整状态、成员规则与长消息响应会增长，消息条数分页不能控制响应体积；50条90KB消息可超过当前RPC 4MiB保护。
- [多宿主验证](../experiments/information-cost/VALIDATION.md)：20组原生对照，严格19/20、判断语义20/20。Codex/DSH短材料工具读取可能增加总输入；Claude CLI的请求模型与响应观测不一致，不按请求型号估价。
- [Luna长材料实验](../experiments/information-cost/LUNA-VALIDATION.md)：全量长记录约60,929 input token，明确身份过滤后直接提供15,390，两次均正确；要求模型自行读取的重复实验出现未调用工具和证据字段不准确。
- [最后验证](../experiments/information-cost/FINAL-VALIDATION.md)：三种临时JS工程、全量/投影、同会话两轮实际文件修改，共12轮全部通过执行检查；当前规格/源码相同，只裁除旧目标无关历史，全程input token减少约27%。另验证真实RPC、MCP与Codex动态工具适配的投影传输。

实验数据为合成任务，小型代码任务不能代表所有工程任务。input包含缓存，不能等同金额。后续测试遵从用户要求全部显式使用Luna，禁止回退到Astra；更早Astra记录仅作为历史结果保留。

## 当前问题与接入位置

`src/bus.mjs` 的 `rules()` 把全体成员能力、全局模型策略和完整 `collaboration.read()` 结果嵌入规则。`collaboration.read()` 的事件游标只分页records，items、requests、outputs仍全量返回。`read`默认返回50条整行消息。`deliver()`与`deliverPanel()`整体序列化投递对象。

新增宿主无关的信息投影层，用在规则装配、回合输入和框架工具返回之前。底层Store、业务 `collaboration.read()`、Web观测API和接受/收尾校验继续读取完整权威对象，不能直接在它们上面删字段。

MCP (`src/rpc.mjs`)、Codex动态工具 (`src/hosts/codex.mjs`) 和Panel工具共用同一投影语义，适配器只负责传输封装。不能各自实现不同的摘要规则。

## 信息分类

| 类别 | 默认提供方式 | 不可省略的部分 |
| --- | --- | --- |
| 稳定规则 | 固定身份、来源与工具/权限规则 | 私聊隔离、契约上限、独立审查、状态责任 |
| 本轮事实 | 直接提供、显式版本 | 当前目标、控制者revision、实际权限、相关工作项revision、待决/阻塞 |
| 当前任务材料 | 完整规格和当前必需源码/证据直接提供 | 不以首尾预览替代执行依据 |
| 无关历史 | 概况/定位引用，按需查询 | 不得丢掉跨项明确依赖和身份未决内容 |
| 可选长材料 | 有界列表、稳定引用、范围展开 | 来源、版本、完整性、续读入口 |
| 存储元数据 | 白名单筛选 | 证据关联与幂等/并发判断所需字段 |

相关性只依赖明确的goalId、workItemId、成果版本、参与责任与显式依赖，不按关键词猜测。普通成员仍可按既有可见性读取共享记录；相关性筛选不收紧也不扩大访问权限。

缺少身份的消息/材料单列 `unresolved`；多个工作项关联全部列出。当前权限、全局运行不确定性、影响团队收尾的未处理责任不能因“与本项无关”被隐藏。旧目标不是一概删除，有明确前置成果引用时仍可展开并核验版本。

## 回合输入与固定规则

固定规则说明：动态事实每轮以本轮权威状态为准，旧轮事实可能过期。成员目录、全局模型策略、完整协作快照不再常驻所有成员规则；模型策略仅在有模型规划职责的上下文提供。

本轮输入至少携带schema版本、团队/目标身份、契约版本、控制者revision、工作项revision、实际执行策略、触发消息与来源引用、必要契约约束、相关阻塞/待决、当前成果与有效证据，以及未决身份材料。规则与工具schema初期保持固定，不每轮增删工具。

Codex原生测试显示，thread/resume接受更新developerInstructions不代表新动态规则生效；稳定规则指向本轮事实的控制组可正确更新。故生产不能依赖规则热更新来传递状态。

现有会话采用显式 `contextSchemaVersion` 兼容：没有确认使用新规则的会话继续旧路径；新格式先用于新建会话。旧规则与新事实冲突时不静默迁移或重建会话，由现有可信重置入口处理。保存每次输入的schema/版本清单，供诊断追溯。

## 工具读取与正文引用

保持现有工具权限、端点key认证、回合来源校验和审计顺序。投影应发生在合法业务读取之后、传输序列化之前；新范围读取每次重新鉴权，不因曾拿到引用而永久可读。

优先扩展现有查询的view、目标/工作项过滤、对象ID和分页参数，避免大量新工具schema增加常驻开销。旧调用兼容；仅新格式会话启用新默认视图。

- 状态默认返回当前目标概况及相关工作项，详情按ID/版本读取；事件分页与当前快照分开。
- 消息列表返回ID/seq、作者、接收者、kind、关联、完整性和有限正文；长正文按引用展开。
- 消息正文已存数据库，直接使用ID+内容哈希引用，不先复制到通用磁盘内容库。不向communication会话开放任意路径读取。
- 范围单位使用Unicode code point或行范围，接口固定其中一种；原型已验证code point分页，不切坏emoji。
- 同一正文产生稳定引用；响应明确next/hasMore/complete，允许显式全文读取。分页游标只推进已扫描/提供的数据，不跳过未交付内容。
- 成果/正文变化、删除、撤权、目标身份不匹配须明确报错。哈希证明内容一致性，不证明正确性或已审查。

字段投影不能把结构化JSON截成碎片。错误、权限、revision和幂等操作回执完整返回。所有原始证据保留，未处理消息仍按原消息ID处置，不以读取预览等同消费或处理。

## 输入预算与完整性

采用字节预算控制框架序列化输入，监测实际宿主token作为效果指标。阈值由实际负载测量后配置，参考仓库8KiB外置阈值不直接成为本项目默认值。

先去除冗余字段和明确无关历史；必要事实超预算时返回明确的分批/完整读取要求，不能悄悄截断。`complete`只说明返回范围的完整性，不代表全团队历史完整或证据充分。

已知必读、可直接提供的短证据直接提供，避免为省少量正文增加一次模型请求。长材料只有在非必读或查询可返回显著较小的相关片段时才适合引用。不能仅凭“请自行读取”保证完成；接受/审查/收尾继续以真实证据和现有结构校验为准，不让模型自报代替权威状态。

## 本次不采用

- 无条件外置所有大输出，以及按首尾预览做最终判断。
- 模型生成摘要作为权限、规格或审查的唯一来源。
- 自动推断跨工作项依赖，静默删除未绑定材料。
- 默认建立项目符号索引、向量数据库或新的模型摘要服务。
- 拦截/改写宿主内部全部请求、删除既有会话历史、静默reset。
- 把独立交接对象变成新的必填汇报流程。先从已有工作项、贡献、审查和接受记录投影，不增加成员劳动。
- 第一阶段建设持久状态增量协议。先利用已有消息游标与定向快照；增量涉及目标切换、删除和游标过期，收益确认后单独设计。

## 实施与发布验收

### 阶段一：确定性投影和测量

实现公共投影模块、固定规则与本轮事实分离、当前目标/工作项详情、按字节约束的消息列表和数据库正文引用。记录规则、回合输入、工具返回各自大小、展开次数、schema和对象revision，不另存密钥或重复敏感正文。

新旧会话兼容，不改变业务权威对象。Panel、MCP、动态工具的鉴权和投影一致性必须做生产入口集成测试；实验传输通过不能代替此项。

### 阶段二：受控启用

按团队或新会话启用，保留旧视图读取和关闭优化的路径，不静默销毁会话。用实际任务比较整个目标的输入、缓存、输出、运行次数、延迟、质量与返工；不同来源不得重复加总。不可获取的金额/用量保持未知。

启用条件：权限和责任链无变化；关键事实/原文可恢复；目标/成果版本切换正确；未决信息显式保留；必要材料不会静默截断；相同任务的输出和执行检查符合要求。发现遗漏权限/关键证据立即停用相关投影路径。对需要全文阅读的任务保留直接提供，不强求统一省token。

设计定稿不豁免以上实现验收。生产模块接入后才评估发布，不把实验目录中的原型直接当成生产代码。
