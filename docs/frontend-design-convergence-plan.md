# 前端设计收敛与外观扩展实施计划

日期：2026-10-31。状态：**已于同日完成全部阶段（A-D）**，批次提交、条目处置与验收记录见 [frontend-design-convergence-audit.md](frontend-design-convergence-audit.md) §5-§6。第 2 节基线按提交 7af3877 核对。

设计依据：[DESIGN.md](../DESIGN.md)。该指南规定目标模型与设计原则，本文规定实施顺序、交付物和验收条件。本文不替代业务契约，不将历史测试结果作为当前版本的验证结果。

## 1. 目标与范围

先将现有分散的颜色、表面、形状、排版、间距、动效与反馈规则收敛到统一职责，再在稳定基线上增加外观能力。收敛阶段维持当前视觉层级与操作行为，允许修正重复样式、不一致状态和可访问性问题，但需在批次说明中列出可见变化。

目标模型为明暗模式、配色主题、材质、动效四个维度；界面密度作为扩展维度，阅读设置独立管理，组合预设保存各维度选择。不是所有现有样式都要强行变成用户选项：布局和交互由共享组件负责，组件尺寸与排版先形成稳定规则，再考虑开放配置。

本轮只交付计划。后续分为“现有设计收敛”和“新能力扩展”两段；前者通过验收后再进入后者。不在收敛阶段引入新材质选择、动效风格选择、密度设置、阅读设置或预设编辑器，不修改团队、权限、模型、投递和会话生命周期等业务语义。

以下来自当前源码静态检查，实施前需重新核对工作区版本与未提交变更。

此前记录的前端布局与全局样式未提交变更已于 2026-10-31 随提交 7af3877 入库：新增 CollapsibleRightSidebar 共享可收起右栏布局，Panel Agent 侧栏基于它重建，globals.css 移除被共享布局取代的规则，DESIGN.md 重写为设计指南。本节基线已按该提交核对，当前工作区为干净状态。若实施开始时又出现并行改动，仍先记录实际基线，不覆盖、清理或回滚，并逐项核对差异；不把所有并行改动都归入本计划。

## 3. 阶段 A：盘点与验证基线

### 工作内容

逐页检查团队首页、团队工作区、Panel Agent、检查与遥测、设置，并追踪它们使用的共享组件。检索硬编码颜色、深色覆盖、背景与阴影、字号与圆角、过渡与动画、滚动策略、内联样式及重复反馈。检索命中只是候选问题：拖动尺寸、图表计算值和确有业务差异的规则不能机械删除。

形成规则台账，每条记录包含：来源位置、使用场景、所属职责、重复或冲突证据、目标归属、处理方式、受影响页面和验证方法。处理方式分为保留、复用现有组件、迁入共享层、删除冗余、暂缓并说明原因。

| 规则类别 | 目标归属 |
| --- | --- |
| 明暗及语义颜色 | 现有主题解析与应用入口 |
| 背景、边界、圆角、阴影 | 共享表面角色及形状规则 |
| 过渡、动画、程序化滚动 | 统一动效用途与当前系统偏好策略 |
| 间距、列表行高、控件尺寸 | 组件内置尺寸和共享布局规则 |
| 字号、行距、内容宽度 | 共享排版规则 |
| 加载、空态、错误、确认、通知 | 现有共享交互组件及反馈规则 |

记录代表性页面的桌面与窄屏截图、浅深主题、侧栏状态和关键交互。记录当前检查结果及已有问题，区分既有缺陷和本轮回归。优先使用现有页面与稳定样例，不触发真实模型请求、安装或控制权变更来获取视觉基线。

### 交付与验收

交付规则台账、代表性页面基线、分批整改列表及已知限制。每项整改均能追踪至真实位置和明确规则；没有证据的问题不列为确定缺陷。完成后才能确定具体共享抽象与迁移范围，不预设必须新增某个目录或配置框架。

## 4. 阶段 B：收敛共享规则

依次执行以下批次。批次保持小而可回退，新增共享规则后立即迁移对应使用点并清理被替代路径，不长期保留新旧两套实现。

| 批次 | 内容 | 完成条件 |
| --- | --- | --- |
| B1 颜色与主题 | 清理页面颜色硬编码、重复浅深覆盖及不一致状态色 | 页面消费语义颜色；主题切换、上传及缺失回落保持可用 |
| B2 表面与形状 | 从现有 Card、浮层、导航和阅读区提取实际存在的表面角色，统一必要边界、圆角和阴影 | 默认实色外观稳定；无需逐页配置材质参数；无无意义的卡片套卡片 |
| B3 排版与尺度 | 收敛文字层级、阅读宽度、间距与列表结构，优先复用组件尺寸 | 长内容、代码、缩放与窄屏可用；不通过缩字或缩小必要点击区域换取密度 |
| B4 当前动效 | 汇总 CSS 与 JavaScript 动效，统一反馈、展开、浮层及滚动等用途 | 仍遵循当前系统偏好；无新增用户选项；不同时存在相互矛盾的动效判断 |
| B5 状态与反馈 | 收敛加载、空态、局部错误、确认和通知，消除同一事件的重复反馈 | 恢复入口及必要确认保留；过期通知清理；不隐藏风险或改变业务语义 |

样式仍在现有全局样式入口和共享组件中收敛。页面只保留布局和有依据的业务差异。已有一次性样式不必全部提升为变量：只有实际复用、需要统一调节或即将变化的规则才进入共享契约。

B4 只整理当前能力。未来支持“用户明确选择优先”时，再统一改造全局媒体查询与局部判断，不能在没有设置入口和迁移策略时提前改变现有系统偏好行为。

## 5. 阶段 C：页面迁移与收敛验收

共享规则落地时同步迁移调用点；本阶段补齐跨页面检查及剩余差异，不等待所有共享代码完成后才开始验证页面。

建议检查顺序：应用骨架与左右侧栏 → 共享会话工作区及团队、Panel Agent 两个使用方 → 首页与设置 → 检查、遥测及其他详情。按台账合并相近问题，避免逐页再造规则。

### 收敛完成门槛

- 重复或冲突规则已处理，暂缓项有原因、影响和后续入口；不要求清除所有页面专属样式。
- 颜色、表面、形状、排版、尺度、动效和反馈均有明确归属，迁移范围内没有功能相同的双重应用路径。
- 原有主题格式、导入校验、旧偏好、首帧快照和回落行为保持兼容。
- 默认外观未发生未说明的大幅变化；已有用户选择不会被重置。
- 会话草稿、选中项、展开状态、历史位置、流式追加、输入与恢复入口未因样式迁移失效。
- 自动化检查与代表性页面验证完成，环境限制明确记录。影响主要任务的未解决回归阻止进入扩展阶段。

交付一份收敛验收记录，列出已改范围、可见差异、验证证据、保留例外及剩余问题，并同步更新 DESIGN.md 中的现状说明。

## 6. 阶段 D：逐项增加新能力

阶段 C 通过后，按下列顺序逐项推进。每项独立交付设置、应用、持久化、回落及验证，避免先堆积所有配置再补体验。

### D1 统一动效选项

增加跟随系统、减少动态效果、简洁、柔和、灵动选项。内部区分风格与减少策略，用户明确选择优先；只有跟随系统响应系统偏好。旧用户默认跟随系统。

替换现有全局与局部判断的优先级，统一处理 CSS、程序化滚动及材质相关运动。验证系统变化、刷新恢复、快速切换、中断、流式追加和减少动效下的静态状态反馈。

### D2 第一种玻璃材质

增加默认实色与一种玻璃材质，先验证导航、上下文、会话操作区、阅读区和浮层的角色映射。不一次实现全部候选材质，不直接将全局 card 改成透明。

从当前配色派生材质颜色，支持浅深模式与失效回落。检查嵌套模糊、浮层可读性、长会话滚动和输入响应；效果不可用时回落实色。已有用户默认保持实色。

### D3 密度与阅读设置

先明确共享参数及测量依赖，再提供密度、字号、行距、内容宽度和代码字号。密度不改变正文大小或业务信息，阅读设置不随主题切换重置。重点验证折叠文本测量、历史位置、输入高度、缩放与窄屏。

### D4 组合预设及统一预览

在已稳定的维度上增加组合预设。实现固定样例预览、应用、取消、恢复默认和自定义组合标记；预览不写入已保存偏好，不触发业务操作。

当前主题点击即保存的行为在此批次显式迁移，不能让一部分维度预览、一部分维度立即保存却无提示。阅读设置默认独立；恢复默认不影响团队、模型或权限配置。预设引用失效的主题或选项时按维度回落，界面如实显示最终选择。

### D5 扩展更多风格

基于已有角色和组合验证结果，再决定纸感、液态折射及其他动效是否值得引入。发现模型表达不足时先修正共享职责，不通过页面分支绕过模型。高级效果的浏览器表现与性能需实测后再确定承诺范围。

## 7. 验证安排

自动化命令从仓库根目录执行，使用现有 scripts：`npm run typecheck`、`npm run test:web`、`npm run build`。共享主题、偏好或交互逻辑变更补充有意义的行为测试；纯视觉与低影响布局调整以浏览器验证为主，不编写镜像 CSS 实现的测试。触及服务端主题契约时再运行相关后端测试与项目要求的检查，不借此计划扩大后端改造范围。

| 变更范围 | 重点验证 |
| --- | --- |
| 主题与偏好 | 内置/自定义主题、缺失回落、旧数据、切换残留、刷新首帧 |
| 表面与布局 | 浅深模式、经典及有色主题、桌面及窄屏、侧栏展开收起、浮层与焦点 |
| 会话与排版 | 长中文、长标识、代码和表格、历史翻页、跟底与向上阅读、输入及草稿 |
| 动效 | 系统减少偏好、快速切换、中断和滚动；D1 后增加用户显式覆盖 |
| 状态与反馈 | 加载、空态、局部错误及重试、断线、确认、通知撤销和去重 |
| 扩展能力 | 代表性交叉组合、配置回落、预览取消、恢复默认及效果降级 |

每批先跑针对性检查，共享层阶段完成后跑前端整体检查。无新增改动、失败或未解风险时不重复运行同一组检查。记录源码检查、自动化、浏览器模拟和真实业务验证各自的范围；未运行的检查不写为通过。

视觉比较使用同视口、同主题和同样例，重点检查文字、边界、布局与交互结果。动画和性能检查在浏览器进行，不能以截图或构建成功代替。

## 8. 风险、回退与执行纪律

| 风险 | 处理 |
| --- | --- |
| 与实施期间出现的并行未提交改动冲突 | 开始实施时重新记录基线，逐块核对差异，不整体覆盖文件 |
| 共享样式影响未迁移页面 | 搜索全部使用点，按共享规则及使用方一起迁移和验收 |
| 主题 radius 等历史字段与目标职责冲突 | 先保留格式与行为；后续确需迁移时单独设计版本与兼容 |
| CSS 与 JavaScript 动效策略不同步 | 收口有效策略，覆盖系统变化和用户设置两条路径 |
| 外观变化导致消息区重建或滚动丢失 | 保持组件身份、数据与布局职责分离，检查流式和历史场景 |
| 玻璃效果成本高或对比度不足 | 限定作用区域与叠加层数，保留实色阅读面及降级 |
| 配置或抽象过度 | 以实际共享规则和已验证差异为依据，不预建所有候选实现 |

每个批次保留清晰差异，避免夹带业务重构。回退只针对本批次的样式、共享规则及迁移使用点；有持久化变化的扩展批次同时提供读取兼容，保证回退后仍能启动。不得通过清空用户偏好、团队数据或工作区改动完成回退。

## 9. 下一步

从阶段 A 开始，交付现有规则台账、页面基线与首批整改范围。依据实际盘点再确定工作量，不在源码盘点前承诺总工期。后续优先完成 B、C，验收收敛结果，再启动 D 的新能力。
