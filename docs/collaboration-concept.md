# Agent Team 协作责任约定

日期:2026-10-25(ADR 0004 后重写)
状态:约定,非框架强制

本文说明减负后"谁负责什么"。这些责任由人和 Agent 在消息层面承担,框架只校验身份、投递与策略域,不再有工作项状态机、审查引用校验或收尾审计。

## 1. 责任划分

| 角色 | 责任 |
| --- | --- |
| 用户 | 提出目标;决定建群、归档、删群;判断何时接受结果 |
| 主 Agent | 把意图整理为可执行的说明;在群消息里分工、跟进、汇总;给出结论与证据 |
| 执行者 | 在授权范围内完成工作,用 send 汇报成果、限制和阻塞 |
| 审查者 | 独立检查成果,以群消息提交意见,不代写成果 |

## 2. 分工的证据约定

框架不强制结构,但真实消息编号仍是可核查的证据:引用他人工作时给出消息编号;审查意见注明针对的成果版本;结论给出依据。收到汇报后依据缺口决定继续、等待、返工或总结;不存在固定轮次。

## 3. 调度

所有成员发给主 Agent 的正式汇报进入唯一 coordination 会话串行处理;不同成员可以并行工作。等待用户决定时只暂停相关工作,其他沟通照常。主 Agent 不建立第二套调度(原生子 Agent、阻塞 wait)。

## 4. 无法完成与终止

材料或决定缺失时,主 Agent 如实说明已完成内容、缺失项和待决定问题,等待用户;不能自行宣布完成。只有用户能归档或删除群;归档保留历史,删除清除框架记录(工作文件与宿主历史保留)。

## 5. 可信入口

建群(交互式 CLI / Panel Agent 私人会话)、归档、恢复、删群、成员增删来自用户入口;主 Agent 通过 group_create/group_add/group_delete 工具动作时,框架创建互动卡等待用户在面板上确认,同意后生效。
