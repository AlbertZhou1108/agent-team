# 从功能出发的公共组件收敛

2026-11-01：针对“全站一致性”的源码梳理与设计方案，不是新增组件均已实现的声明。上游：[五维配置](component-configuration.md)。此前迁移裸 details 只覆盖一种实现形态，不能作为折叠功能已经收敛的证据。

## 分析方法

先列用户任务与状态转移，再找全部使用处，比较交互责任，确定公共能力和场景组合，最后设计参数。复用层次：

1. 行为能力：状态控制、键盘、焦点、隐藏交互、可中断转移、清理。
2. 功能组件：完整承担一种交互，如分组展开、导航选择、内容截断展开。
3. 场景组合：侧栏、记录面板、成员列表、输入区；提供业务内容，不再实现底层交互。
4. 呈现配置：五维参数与预设；控制组件外观和动效，不改变导航目标、权限或数据含义。

不以相同 CSS 或组件数量减少作为收敛标准。相同任务应有一致操作与反馈；不同任务可共享能力而保留功能组件。提取必须有真实重复使用处，不预建无使用者的万能组件。

## 折叠功能的完整分类

| 用户任务 | 已发现的使用处 | 共享方式与边界 |
| --- | --- | --- |

以上为代表模块清单，尚不声称每个调用点都已逐一验收。优先扩展已有模块，只有交互职责缺失且有多处复用需求时才新增公共组件。

## 执行与验收

### 审计修订与执行门槛（2026-11-01）

源码自审发现以下遗漏，修订后通过方案审计；这不是独立审查或全站实现验收：

1. 原表是代表模块，不是可关闭的迁移清单。每批必须登记具体入口、状态来源、持久化归属、特殊动作、组件归属和证据；未登记项不得算已覆盖。
2. “后四类未收敛”表述不准确：详情类已有部分实现，分组也仍有缺口。应逐场景记录，不能按表格行的位置判断完成度。
3. 受控/非受控状态、默认展开、禁用、异步加载、渲染保留/卸载、嵌套和受外部导航驱动均须纳入接口。尤其受控组件不能在调用方拒绝更新时自行改变状态。默认保留内容；懒加载由调用方响应 open，禁止迁移时额外发起请求。
4. 复合标题的搜索、创建、已读操作必须位于触发按钮之外；不能把输入框/按钮嵌入另一按钮。标题描述与计数的可访问关系也应保留。
5. 所有功能族都依赖焦点、滚动和辅助模式，因此不能把这些能力推迟到最后才处理。每批先保护这些约束，再推进外观。
6. 补充直接操作与内容输出功能：拖放排序、拖动尺寸、复制、下载、附件预览/上传；纳入集合/尺寸/阅读对应族。需保留草稿、选择与事件隔离。
7. 静态扫描只防明确回退，不禁止合理使用底层 Collapsible，也不证明运行时一致。新增公共接口先在两个真实场景验证，不用万能包装强行迁移。
8. 当前工作区已有大量未提交修改。按文件增量迁移，保留用户与历史修改，不回滚或重装组件；每批修复失败检查后才继续。类型检查不能代替 SFC 生产编译。

执行批次：A 补齐分组标题组合与受控语义；B 摘要、面板与输入区的折叠能力审查；C 导航/选择/集合；D 信息/状态；E 表单/菜单/弹层/反馈。焦点、滚动、阅读、辅助模式是各批验收横切项。每批允许保留有明确理由的场景组合，不通过复制交互实现绕过公共能力。

按功能族推进，每族闭环包含：使用处清单 → 共同/特殊行为对照 → 确定复用层 → 公共接口与五维消费 → 迁移 → 代表场景验收 → 治理防回退。

优先顺序：①补齐折叠分类和标题组合；②导航/选择/集合浏览；③信息承载与状态展示；④表单/动作/弹层/反馈；⑤滚动/阅读等交叉能力。现有功能正确性与高频场景优先，不以一次全量替换冒充全站收敛。

每族至少核对：默认/交互/禁用/加载/失败状态，鼠标与键盘，嵌套/快速中断/卸载，长文本/窄屏/缩放，实色/玻璃/纸质代表组合，个人密度与阅读设置。业务状态持久化、网络请求与选择权限不迁入视觉组件。

完成标准：同一功能的全部已登记使用处都有组件归属或明确例外；调用方只提供数据、动作和必要布局；预设通过同一参数改变呈现；行为和视觉分别有证据。仅“都用了组件库”或“截图类似”不足。

### 批次 A 回归修正

用户验收发现两项遗漏：description 放在折叠区外，主题收起仍显示说明；TelemetryMembersView 仍按原生 details 的方式单向绑定 open，严格受控后点击无效。已把 description 纳入同一 CollapseReveal，并用独立 detailsOpen 双向绑定详情开合；选择成员时主动展开，切换团队时重置。复测包含点击展开/收起、切换成员自动展开、主题收起后说明位于 inert 隐藏区域。说明归属增加了修复前失败、修复后通过的回归测试；前端共 153 项通过。此问题说明公共状态契约调整必须复核全部调用方，SSR 与组件静态检查不能代替真实业务入口交互验证。
