# 扩展验证：模型信息利用与宿主边界

日期：2026-10-23。状态：已进行原生模型与框架测试，不将方案直接定稿。所有模型输入为合成任务，工作目录和通信 socket 隔离，不接触正在运行的用户团队；使用本机已有模型配置，未安装或更改配置。

## 测试层次

- 现有完整核心套件：102/102 通过，含 Panel HTTP、目标生命周期、控制者与策略、审查/接受、消息调度、遥测及适配器测试。其中许多使用 fake host，不能替代原生宿主验证。
- 信息层实验：6/6 通过，真实 Bus/SQLite，验证大消息响应、快照增长、范围引用、撤权、游标与装配入口。原型不接生产，不等于新功能集成回归完成。
- Codex 原生：从实时目录选择 gpt-6-luna 与默认 gpt-6-astra，low，四种场景分别全量输入/目录加按需读取，16 组。场景为中部错误、跨目标旧审查、当前契约与旧权限冲突、缺失独立证据。
- DSH 与 Claude CLI：各运行全量/按需日志场景，通过真实 MCP stdio → 框架 RPC 客户端 → 隔离 socket broker 取得原文，共4组。broker只服务合成只读工具，验证的是传输和读取能力，不是生产引用的完整授权链。
- Codex 原生会话：同会话三轮动态 developerInstructions 实验，加上另一个同会话两轮稳定规则/本轮状态对照，共5轮。工具集合保持不变。

每个模型场景只跑一次，未随机化顺序；小型受控实验证明具体能力与反例，不能估计总体准确率或固定节省比例。没有真实编码交付质量基准，不声称全面验证了模型所有能力。

## 原生续接发现

原生 Codex 初次规则 CURRENT_CODE=REV_1_ONLY，第二轮 thread/resume 传入 REV_2_ONLY，输出仍为 REV_1_ONLY。第三轮把新事实写进用户输入也仍返回旧值，因为原有高优先级规则明确要求只取规则中的值；这属于有意构造的优先级冲突，不能用来证明正常本轮事实更新无效。

控制组从新会话开始固定规则：CURRENT_CODE 是动态事实，以每轮输入为准。两轮输入 STATE_1、STATE_2，分别正确输出 STATE_1、STATE_2。

结论：当前宿主路径下，不可依赖 resume 更新 developerInstructions 的动态内容；稳定规则授权本轮输入承载动态事实在该控制组可行。已有会话如果保留冲突旧规则，不应静默迁移；需明确会话版本/兼容策略，不能假设改框架 rules() 就能立即修复所有旧会话。适配器请求成功也不证明规则已更新。

## 用量计量

Codex 的同一 native turn 有多次相对回合起点的用量更新；本报告取最后一个有用量的 codex.thread_token_usage 记录，不把多次更新累加。DSH 按 step 的 usage 相加；Claude 使用 result_usage 回合汇总，不再次相加 assistant request 记录。保留缓存/非缓存分项，不把总输入直接当成费用。

Claude 的目录/请求/初始化报告 claude-opus-5[1m]，assistant 与本机 transcript 报 deepseek-v4-pro。故这里只称 Claude CLI 宿主测试，不能称 Anthropic Claude 模型能力测试，也不能按请求模型价格估价。DSH 请求观测为 deepseek-official/deepseek-flash，high；这仍是宿主观测，不是外部服务身份认证。

原始观测保存在 native-model-results.json、native-extra-results.json、cross-host-results.json 与 native-resume-results.json。summary.json 仅做去重和判分汇总。

## 判分注意

gpt-6-luna 的 stale-review/full 返回 accept=false、evidence="当前成果v3"。它的拒绝与版本含义正确，但不满足要求的精确字符串 "v3"，严格判分失败。汇总单独标记 semanticPass，不把格式问题夸大成错误接受成果，也不悄悄覆盖原始判分。

## 对方案的影响

1. 不采用“所有工具结果先外置再读取”的统一默认。此次短日志中 Codex、DSH 由于追加模型请求，总输入增加；Claude CLI 这组下降。按需读取具备能力，不等于按需读取始终节省。
2. 优先消除无需理解的结构性负载：历史工作项/输出重复注入、数据库冗余字段、无关目标。必要当前事实直接提供，可能需要的长材料给引用，明确必读材料一次提供。
3. 工具 schema 和宿主固有前缀也占输入。数百字正文的减少，可能不足以抵消再运行一次模型；不能仅按正文大小做决定。缓存计费和输出也需要一起评估。
4. 维持固定规则、每轮显式动态状态；先设计新旧会话兼容方案。对旧规则冲突做失败可见，而不是静默继续。
5. read 的条数分页不足以约束体积：实验50条90KB消息可超过现有RPC 4MiB响应保护。需要字节预算加引用，不只调小默认条数。
6. 按模型场景分别保留全量与定向读取选项，不能用一次读取成功规定所有成员都采用某种输入方式。
